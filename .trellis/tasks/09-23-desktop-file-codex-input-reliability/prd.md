# 桌面文件菜单与 Codex 交互输入可靠性

## 目标与范围

- 修复桌面端文件树右键菜单的复制、剪切、粘贴和打开所在文件夹“点击后无效或无反馈”；复制／剪切文件后既能在应用内其他目录粘贴，也能在 Windows 文件资源管理器粘贴；删除已有功能不得回归。这里不新增浏览器打开 HTML，也不扩展 Web 文件树写入能力。
- 验证 Codex 的异步提问是否暴露可靠 Hook 事件；若可用，补齐安装、状态、信任、传输和通知链路。不得将普通工具调用误报为提问。
- 在 Codex 交互界面实现用户期望的 Ctrl+A 全选、Ctrl+Z 撤销、Ctrl+Y 重做，以及左键点击输入文本后把编辑光标定位到点击位置；不能用视觉高亮、隐藏光标或仅移动 xterm 显示光标冒充真实输入定位。

## 分阶段验收

### 1. 先复现并确认能力边界

- [ ] 对文件、目录、搜索结果、单选与多选逐项复现四个菜单动作，记录内部剪贴板、系统剪贴板版本、目标路径、IPC 返回和用户反馈。明确哪些是实际失败、哪些是静默成功或预期冲突。
- [ ] 验证“复制／剪切”应用内与 Windows 文件资源管理器双向目标语义：系统级文件剪贴板格式、剪切标记、权限、WSL／SSH 路径和跨应用风险均需明确，不能以文本路径冒充文件剪贴板。
- [ ] 运行与项目支持版本相符的 Codex，观察同步／异步提问的真实 Hook 事件、工具名和信任状态；若异步工具不经过 Hook，记录可靠的官方事件入口或明确报告不支持，不能靠终端文本猜测。
- [ ] 对 Codex TUI 的普通输入、自动重绘、换行、中文／宽字符、粘贴和鼠标操作做最小复现：证明编辑光标位置与输入内容的权威状态从何处获得；区分 TUI 自身重绘、PTY 输出排队和 CLI-Manager 二次输入镜像造成的闪跳。
- [ ] 若无法可靠读取或控制 Codex TUI 的输入状态，先给出可复现证据和替代交互方案，暂停 Ctrl+A/Z/Y 与鼠标定位的实现决策，不交付假支持。

### 2. 文件菜单

- [ ] 复制／剪切后用户能看到有效反馈；粘贴到另一目录能正确复制／移动，目标冲突、同目录操作、项目切换和外部剪贴板变更有明确结果，不能静默无效或误操作其他项目。
- [ ] Windows 本地文件／目录复制或剪切后可在资源管理器粘贴；资源管理器剪贴板被其他应用覆盖后，应用内不会误用过期快照。WSL／SSH 等非本地路径明确提示不支持系统级文件粘贴，不写入虚假的 CF_HDROP 路径。
- [ ] 打开所在文件夹对本地文件、目录和搜索结果能打开正确位置；WSL／不可用路径给出可理解的失败提示，不将进程启动成功误当成目标已成功打开。
- [ ] 删除确认、路径约束、脏文件保护及 SSH 只读行为不回归。

### 3. Codex Hook 与输入

- [ ] 如果异步提问存在可靠事件，安装／卸载／状态检查、local／WSL／SSH、前台／后台和通知去重均通过验证；Hook 缺失或不可信时状态明确。
- [ ] Ctrl+A 的真实 Codex 草稿被选中；Ctrl+Z/Y 按实际编辑历史撤销／重做；左键点击可定位真实草稿编辑光标。三者在多行、换行、中文、输入法组合及 TUI 重绘后仍一致，不产生光标乱闪、跳位、重复文字或误提交。
- [ ] 普通 PowerShell/CMD/Pwsh、WSL/Bash、其他 TUI 保持原生快捷键和鼠标语义；特别不能把 shell 的 Ctrl+Z 作业控制无条件改成撤销。
- [ ] 关闭“隐藏 Codex 运行时光标”也能正常使用；该设置只允许作为偏好，不作为验收修复手段。

## 必测状态

窗口焦点／失焦、分屏和深层分屏、最小化、多个会话与 Workspan、项目及 Worktree 切换、文件树展开／收起、local／WSL／SSH、Hook 已装／未装／旧版、Codex 正在输出／空闲／等待提问、终端尺寸变化、不同字号与中文输入法。

## 不做

- 本任务不顺带改 Web 端文件编辑或远程文件写入。
- 不全局拦截 Ctrl+Z/Y，也不把一串模拟方向键当作通用 TUI 光标定位方案。
- 不修改 Codex 自身配置或第三方 Hook，除非确认 CLI-Manager 已拥有对应配置项且有安全升级／卸载路径。
