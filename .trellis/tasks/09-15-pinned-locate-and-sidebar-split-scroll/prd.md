# 已置顶项目右键定位位置与侧栏分区滚动

## Goal

① 已置顶项目右键菜单首项新增「定位位置」：滚动定位到主列表中该项目并高亮；② 侧栏拆分为置顶区与项目列表两个独立滚动区域（VS Code 式，滚轮作用于鼠标所在区域）；③ 两区域之间新增分隔线。

## Requirements

### 0. 前置决策（已与用户对齐）

| 项目 | 用户选择 |
|---|---|
| 「定位位置」行为 | 滚动到主列表中该项目并高亮（**不是**打开文件夹——菜单已有「打开目录」） |
| 分隔符位置 | 侧栏内、置顶区与普通项目列表之间（**不是**菜单内） |
| 置顶区滚动 | 拆成两个独立滚动区域，VS Code 逻辑：滚轮作用于鼠标所在区域 |
| Trellis 任务 | 建（本任务） |

用户答复原文：「滚动定位并高亮」／「左侧栏置顶区域和普通项目之间」／「分成两个区域分开滚动，类似于 vscode 逻辑，按照鼠标所在区域」。

### 1. 「定位位置」菜单项

- 仅在**已置顶项目**（`PinnedProjectItem`）的右键菜单出现，且位于**第一位**，排在现有「打开终端」之前。
- 「定位位置」与其余菜单项之间插入一条分隔线（复用现有 `context-menu-separator`）。
- 需要区分右键来源：主列表项目行与置顶副本共用 `contextMenu.kind === "project"`，因此菜单状态需携带来源标记（如 `fromPinned: true`），否则会给所有项目行都加上该项。

### 2. 定位行为

- 若当前筛选不是「全部」（`projectFilter !== "all"`），先切回「全部」，否则项目可能不在树中。
- 展开该项目所有**折叠的祖先分组**（`collapsedGroupIds`），否则节点不会被渲染、无法滚动。展开沿用与手动展开一致的语义并**持久化**（用户 2026-09-15 决议，见 `design.md`）。
- 滚动到该项目行并高亮。
- **重复调用必须仍然生效**：项目已选中且已可见时，第二次点击也要重新滚动（现有滚动副作用依赖 `selectedTreeKey` 变化，同值不会重跑，需要额外的触发信号）。
- 无法定位时必须给出提示（用户 2026-09-15 决议），不能静默无反应。分原因用 `sonner` toast：
  - 路径无效（`pathInvalid`）的项目 → 错误提示，附带项目路径；
  - 搜索态（`searchOpen && searchQuery` 非空）导致该行不可见 → 提示先清空搜索；
  - 其他 `visibleNodes` 中不存在该项目的场景 → 提示项目不存在。

### 3. 侧栏分区滚动

- 置顶区与项目列表成为两个独立滚动容器，各自有滚动条，互不影响。
- 滚轮/触控板作用于鼠标指针所在区域（用原生嵌套滚动容器即可实现，无需 JS 拦截滚轮事件）。
- 高度分配按项目数量弹性，上限**三七分**（用户 2026-09-15 决议）：置顶区按内容高度收缩，最高占可用高度 30%，达到上限后**内部滚动**；项目列表始终至少占 70%。
- 两区域之间新增可见分隔线。

### 4. 约束

- 不改依赖、不改数据库结构/迁移、不改 IPC 契约、不改 PTY/daemon/proxy、不改 SSH 语义。
- 新增用户可见文案必须同时覆盖 `zh-CN` 与 `en-US`（`src/shared/i18n/messages/` 按领域维护，走 `useI18n()`）。
- 交付前更新 `CHANGELOG.md`（无版本号 → `TEMP`）与 `docs/功能清单.md`（归入「侧边栏项目树」板块）。
- 本任务前序会话已有一批未提交的侧栏样式改动，属于另一件事，不得回退、也不并入本次 delta。

## Acceptance Criteria

- [ ] 右键已置顶项目，菜单首项为「定位位置」，其后有一条分隔线，再是原有「打开终端」等项。
- [ ] 右键主列表中的普通项目行，菜单**不出现**「定位位置」。
- [ ] 点击「定位位置」后：筛选切回「全部」→ 祖先分组展开 → 该项目行滚入可视区 → 该行高亮。
- [ ] 项目位于折叠的父文件夹内时，点击「定位位置」能展开并滚动到位；多层嵌套的祖先分组同样全部展开。
- [ ] 展开祖先的结果被持久化：定位后重新加载侧栏，祖先分组仍为展开状态（与手动展开一致）。
- [ ] 筛选处于「已开启」或「已置顶」时，点击「定位位置」能切到「全部」并定位成功。
- [ ] 项目已选中且可见时，再次点击「定位位置」仍会重新滚动（不静默无反应）。
- [ ] 项目路径无效时点击「定位位置」，出现错误提示且包含项目路径，不是静默失败。
- [ ] 搜索态下该项目不可见时点击「定位位置」，出现提示引导清空搜索。
- [ ] 置顶区与项目列表各自独立滚动：滚动其中一个，另一个的滚动位置不变。
- [ ] 鼠标悬停在置顶区滚动时，只有置顶区滚动；悬停在列表上滚动时，只有列表滚动。
- [ ] 置顶项很少时置顶区按内容高度收缩，不占满 30% 上限。
- [ ] 置顶项很多时置顶区不超过可用高度的 30%，超出部分在置顶区内部滚动，项目列表仍保有不小于 70% 的高度。
- [ ] 两区域之间存在可见分隔线。
- [ ] 侧栏展开／折叠／紧凑（compact）三种形态、以及 embedded 模式下均正常，无布局溢出或高度塌陷。
- [ ] 既有交互无回归：右键菜单的滚动位置保持、树内键盘导航与焦点、拖拽排序与拖入分组、分组折叠展开、文件浏览器切换、快捷键删除。
- [ ] `zh-CN` / `en-US` 双语切换后新增文案均正确，时间格式不变为 12 小时制。
- [ ] `npx tsc --noEmit` 与定向测试通过；`CHANGELOG.md`（TEMP）与 `docs/功能清单.md` 已更新。

## Notes

- 「定位位置」语义已澄清为**列表内定位**，与菜单中已有的「打开目录」（`sidebar.menu.openDirectory`）、「浏览文件」不重复。
- 置顶项是主列表节点的**副本**：其 `data-tree-key` 为 `pin:p:<id>`，主列表为 `p:<id>`（分组 `g:<id>`、Worktree `wt:<id>`）。定位的真实落点是主列表的 `p:<id>`。
- 已知待处理的机制冲突见 `design.md`「与既有右键滚动保护的冲突」。
- Keep `prd.md` focused on requirements, constraints, and acceptance criteria.
- Lightweight tasks can remain PRD-only.
- For complex tasks, add `design.md` for technical design and `implement.md` for execution planning before `task.py start`.
