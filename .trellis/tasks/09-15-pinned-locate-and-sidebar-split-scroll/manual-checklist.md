# 人工验收清单（待用户执行）

> 实现已完成并通过自动检查（`npx tsc --noEmit`、`node --test scripts/pinnedProjectLocate.test.mjs` 9/9、侧栏与架构相关既有测试 18/18）。以下步骤需在运行中的应用里人工确认——自动化测试只做源码断言，无法验证真实滚动与鼠标命中行为。

## 批次 1 · 侧栏分区滚动

- [ ] 展开侧栏，置顶若干项目并在项目列表中滚动：置顶区位置不变。
- [ ] 鼠标悬停在置顶区滚动滚轮：只有置顶区滚动，列表不动。
- [ ] 鼠标悬停在项目列表滚动滚轮：只有列表滚动，置顶区不动。
- [ ] 两区域之间存在可见分隔线，且不抢视线。
- [ ] 置顶 0 个项目时，置顶区与分隔线不出现（或按设计表现），列表占满高度。
- [ ] 置顶项很少时，置顶区按内容高度收缩，不占满上限。
- [ ] 置顶项目很多时，置顶区不超过可用高度的 30%，超出部分在置顶区内部滚动，项目列表拿到剩余空间。**注意**：分隔线自身占位约 9px，因此列表区最坏约为 68.9%（实测值），若你期望列表区严格 ≥70%，需要缩小分隔线上下 margin 或放宽置顶区上限，请告知取哪一项。
- [ ] 侧栏宽度拖到最窄、折叠为竖栏、切到紧凑模式、`embedded` 模式下均无高度塌陷或双重滚动条。
- [ ] 右键打开菜单时侧栏不跳动（既有滚动保护未回归——注意该保护此前目标是 `scrollTop` 恒为 0 的外层容器，本次修正后它才真正生效，需重点确认长列表下右键不再跳动）。

## 批次 2 · 定位位置

- [ ] 项目在根层：点击「定位位置」滚动到位并高亮。
- [ ] 项目在一级折叠分组内：点击后分组自动展开并滚动到位。
- [ ] 项目在多层嵌套的折叠分组内：点击后所有祖先分组展开并滚动到位。
- [ ] 筛选为「已开启」时点击：自动切回「全部」并定位成功。
- [ ] 筛选为「已置顶」时点击：自动切回「全部」并定位成功。
- [ ] 项目已选中且已在可视区：再次点击仍会重新滚动（不静默无反应——这是 nonce 机制要守住的点）。
- [ ] 连续快速点击两次，滚动行为一致、不互相打断。
- [ ] 项目路径无效（红色路径标注）时：定位仍应成功——该项只负责滚动定位，不校验路径、不打开目录。
- [ ] **残留搜索词**（在「全部」下输入搜索词 → 切到「已置顶」→ 右键置顶项 → 定位）：若该项目被该搜索词过滤掉，出现「无法定位该项目」提示，而不是静默无反应。
- [ ] 搜索命中该项目时定位：正常滚动到位。
- [ ] 定位成功后：该项目在列表中被选中高亮（选中态为左侧色条 + 单层主色底）。
- [ ] 定位后重新加载侧栏：被展开的祖先分组仍保持展开（持久化生效）。
- [ ] 定位后滚动位置**不会**在约 50–150ms 后被弹回原位。

## 批次 3 · 菜单与文案

- [ ] 右键置顶项目：首项为「定位位置」，紧随一条分隔线，然后是原有「打开终端」等项。
- [ ] 右键主列表中的普通项目行：菜单中**没有**「定位位置」。
- [ ] 多选批量态（`showProjectBatchContextMenu`）下：不出现「定位位置」。
- [ ] 菜单内键盘上下导航、Escape 关闭、点击外部关闭均正常。
- [ ] 切换到英文界面：新文案与 aria-label 均为英文，无中文残留（「定位位置」→「Locate in List」）。
- [ ] 英文界面下时间格式仍为 24 小时制。

## 已知范围

- 本任务不改 PTY/daemon/proxy、SSH、数据库结构、IPC 契约与依赖。
- 三项决策已落定（展开祖先持久化、不可定位给提示、置顶区上限三七分内部滚动），依据见 `design.md`「已决议」。其中「展开祖先持久化」为按用户表述推论，验收时请确认该行为符合预期。
- 已放弃的一项：原计划「定位时取消右键滚动保护的恢复定时器」经实测证明冲突不存在（从置顶行右键时 `closest(".ui-sidebar-main-scroll")` 为 `null`，恢复逻辑提前返回），故未引入可取消句柄。
- 已做的自动验证：无头渲染实测了高度约束链（30% 触顶精确、`min-h-full` 正常解析、外层容器不溢出），详见 `implement.md` 的「布局实测」。但该 harness 不含主题色与真实字体度量，**观感（分隔线粗细/间距、30% 上限手感）仍需在运行中的应用里人工确认**。
