# Claude 终端答后宠物待处理项清除

## 目标

用户在 Claude Code 终端完成问答后，宠物E 的对应待处理项能够及时清除，不再要求安装子任务 Hook 才能完成清理。

## 已确认范围

- 仅修改 CLI-Manager；不修改已安装的 Claude 配置、Pi 或 rpiv 源码，不安装、运行、编译、测试或推送。
- 版本记录归入 V1.4.3；基线为 a131b93dd63980c75c9a37d0b0bfdea241ae6514。
- 使用真实工具结束信号，而非进程存活、普通 PTY 输出、旋转文字或 PreToolUse 来推断用户已回答。
- 保留 broker 的会话、工具调用身份及提交中保护，不将交互项改成整会话无条件清空。
- Pi 已有可可靠代答的接口保持原样；不能可靠代答的自绘问卷不再强行接管。本任务不实现新的 Pi 协议。

## 验收条件

1. 仅安装 Claude attention 模块时，也有问答结束所需的回调；旧安装缺少结束回调时不能误报 attention 已完整安装。
2. attention 与 subagent 任意安装顺序都不重复注册问答专用完成命令，两类回调分别管理。
3. 卸载 subagent 不移除 attention 的提问或完成命令；卸载 attention 不破坏 subagent 的生命周期。
4. 两个模块均卸载后不遗留托管完成命令，其他来源和用户命令保留。
5. 成功结束与工具执行失败均能通过专用内部事件清理待处理项，Agent/Task 的工具 ID 不丢失；问答完成不得触发子任务界面或通知。
6. 匹配的终端完成事件清除对应待处理项；不同会话、不同工具 ID、开始/心跳事件不能撤销交互项，已提交待确认的答案仍能正常确认。
7. 清楚区分已完成静态检查和未执行的回归测试；不宣称真实 GUI 已验证。

## 授权

用户在查看静态根因、修改范围和回归方案后明确选择“按上述方案修复”，并同意建立对应 Trellis 记录。此次只修复已确认的安装依赖，不扩大 broker 的清除条件。
