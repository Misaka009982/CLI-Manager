# MCP/Skills 项目隔离与交互

## Goal

V1.4.0 次要增强：项目能力适配与交互，落实父任务 ../09-10-mcp-skill-management/prd.md 的 R6–R8。全局一处维护优先；项目无法实现时明确仅支持全局，不阻塞全局交付。

## Requirements

- Grok 允许接管进程 GROK_HOME，但原始 Home 的配置必须完整继承，仅注入 MCP/Skills；不能改变认证、历史、Hook、供应商、权限及插件其他功能。依赖父任务受管 Home 等价性原型，未通过前不宣布项目隔离支持。

- 项目/Worktree每CLI的MCP/Skills独立inherit/custom，草稿与有效集合预览；按项目身份生成启动快照，与供应商配置合并并接入新建/resume。
- 依赖模型、部署及全局可复用列表。遵循父任务 decision.md：按 CLI/环境/版本对 MCP、Skills 分别判定；不支持项禁用自定义，说明无法达到项目设置效果、仅使用全局，并提供全局设置入口。

## Acceptance Criteria

- [ ] 原始非扩展配置改变后，新启动/新进程恢复继承最新基线；现有进程及重连保留旧快照，MCP/Skills 集合不串用；认证刷新、历史新增与恢复不受配置快照冻结影响。此同步时机已获用户确认。

- [ ] 支持项 A=ABC、B=BCD 并发正确；同路径不同项目和Worktree不串用；空集合全关；取消不写盘；旧会话待应用明确；无Hook仍能管理。
- [ ] 不支持项中英文提示仅支持全局，显示实际全局状态，正常启动全局会话；已有自定义失效时标为未应用并在启动前提示，不静默生效或删除草稿。MCP/Skills 支持状态独立；可修复错误与能力不足分开。
- [ ] 满足父任务对应要求与跨层验收。

## Planning status

V1.4.0平台范围已确认：Windows与macOS本机、Windows下WSL均必须支持；SSH远端管理延后。对应功能须逐平台验收，不得以Windows单平台通过代替macOS/WSL验证。

已确认项目策略仅对CLI-Manager启动/恢复的会话生效，外部终端直接启动不在范围内。项目策略通过启动快照注入，不改写原生全局/项目配置来实现隔离。
验收补充：新建与创建新进程的恢复使用当前策略；重连已有进程保持原快照；外部终端不受项目策略变更影响。无法注入的自定义启动命令须明确显示未应用。

当前planning，产品范围已确认；保留父任务技术验证关卡，未经审阅不开始实现。
