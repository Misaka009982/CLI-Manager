# Pi 问卷的四色灯等待状态

## 目标

rpiv 使用 Pi 自绘问卷时，宠物E 能显示该会话正在等待终端作答；不要求也不伪装宠物代答。

## 用户确认的范围

- 仅修改 CLI-Manager，不修改已安装插件或 `rpiv-mono` 源码现场。
- 实现以独立外挂和既有 fork 独有文件为主，上游共有文件仅保留少量必要接口，不在上游大模块内堆积业务逻辑；提供后续同步的接入清单。
- 继续 `integrate/v1.4.3-desktop-pet-e`，记录归入 V1.4.3。
- 在当前 worktree 中实现、静态核查、单独提交，再快进推送 `origin/master`；不创建 PR。
- 保留 `.trellis/tasks/10-14-pi-question-adapters/` 的未跟踪文档，不纳入本次提交。
- 不编译、不运行测试、不安装依赖或启动服务；用户本地执行运行验证。

## 验收要求

1. rpiv 问卷打开且未完成时，该 Pi 会话计入黄灯。
2. 只读等待项只提供返回会话入口，不提供回答或提交按钮。
3. 正常回答、取消后取消等待状态；继续执行、完成、失败依照真实生命周期显示。
4. 终端关闭、Pi 切换会话或关闭、daemon 重启，以及结束消息丢失时，不无限残留黄灯。
5. 多会话互不串联；迟到和重复消息不复活已结束的等待，不清除新一轮等待。
6. 已有可代答请求继续工作，等待状态不替换或撤销真实的 `pendingAction`，同会话不重复计数。
7. 不依赖 `notificationsEnabled` 或 `agentInteractionEnabled`；宠物总开关仍然有效。
8. 普通通知仍不进入四色灯待答数量；保持原有红/蓝终态清理规则。
9. 适用于当前 Pi 1.2.0 暴露的正式对话框生命周期，保留旧版标准对话框代答；不承诺没有正式事件的旧版自绘问卷支持。
10. 新文案中英文对称；模板变更同步升级托管版本，记录升级生效步骤。

## 不做

- 屏幕文字、转圈字符、输出活跃度或进程存活的作答完成猜测。
- rpiv 私有协议、问卷数据回填、工具替换、新问答工具或第三方补丁。
- 新监听端口、依赖、数据库或用户设置变更。
- 本轮扩大 SSH Agent 协议或修改 Claude 已有审批清理规则。
