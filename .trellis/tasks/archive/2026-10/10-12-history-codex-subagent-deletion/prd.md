# 历史子代理删除可靠性

## Goal

修复本地 Codex 子代理历史的删除按钮禁用，并让确认删除、真实文件删除和应用状态清理一致。

## Requirements

- 本地 Codex 独立 rollout 子代理可确认后单独删除；不根据当前分页/筛选结果猜测父记录是否存在。
- 删除父会话时，按同一 Codex 历史根内原始 `source.subagent.thread_spawn` 元数据查找全部后代，覆盖不同日期/工作目录。
- 普通 `forked_from_id` 分叉、相邻但无关系的 rollout、其他根、SSH/只读行和收藏副本不受级联影响。
- 保留来源/项目/路径校验、备份完整目标集、失败回滚和手工恢复锁；不修改消息编辑/转换资格。
- 批量删除按后台实际覆盖的记录合并执行，避免父会话已经删除子代理后再次删除时报错。
- 用户同意新任务/独立分支，沿用 1.4.3；提交后只构建 NSIS，不自动安装、同步分支或推送。

## Acceptance Criteria

- [x] 真实元数据形态的孤立/非孤立 Codex 子代理可删除，父记录和兄弟记录保留（隔离夹具验证）。
- [x] 父会话的跨日期、多层子代理正确级联，普通分叉和其他根保留。
- [x] 重复身份、链接越界、备份失败和 Windows 锁定文件失败不导致部分丢失。
- [x] 列表、单删、批量、Store/搜索清理使用相同资格与真实删除结果。
- [x] 定向前后端测试、类型检查、Rust 检查和 strict architecture 通过；1.4.3 NSIS 构建完成并记录哈希。
- [x] 用户安装后确认此前禁用的真实记录可以删除（2026-10-12；未代用户删除真实历史）。

## Notes

- 诊断确认用户所指项目目录与子代理日志存在；原始元数据明确为 subagent，父 ID 未在当前盘点发现，缺失原因未知。根因不是项目目录被删除。
