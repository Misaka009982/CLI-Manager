# V1.4.0 技术方案与能力边界收敛稿

状态：全局优先、项目能力不足时仅使用全局的原则已获用户确认；四个子任务已按本文路线完成产品实现和独立审计，当前为父任务集成验收。本文仍是能力边界入口，覆盖旧设计/报告中“项目隔离必须全部通过才交付”及“拒绝启动”的建议；实验报告保留为证据。

实施授权更新：用户已明确要求按本计划实施，不需要再次询问需求或实施意愿。已从 extension-model-adapters 开始，依次完成导入/同步、全局管理和项目管理；授权、实现状态与未通过发布门禁分开记录。

首要交付：全局 MCP/Skills 一处维护、各 CLI 使用。项目管理是次要增强，不能实现时明确展示仅支持全局，不因某 CLI 项目能力限制阻塞全局管理交付。

## 1. 确定的实现路线

- 权威数据：版本化 JSON MCP 定义；字段语义适配 Claude JSON、Codex/Grok TOML。保留未知厂商字段、来源与秘密引用；不维护三套可编辑权威配置。
- Skill：应用数据目录保存版本化完整包；auto/symlink/copy 部署。外部文件不冒充受管所有物，权限失败仅 Skill 部署可回退复制。
- 导入：cc-switch 只读、原生配置/目录、GitHub 地址；预览→冲突处理→导入→显式部署。Profile 不自动当作项目策略，导入不反向修改源。
- 策略：环境/CLI/项目/Worktree 标识，MCP 与 Skills 独立 inherit/custom；自定义空集合为受控范围全关。企业强制限制优先，不能绕过。
- 会话：策略仅应用于 CLI-Manager 新启动/新进程恢复；重连不重新注入。原始配置与策略版本组成启动快照，不切换全局文件来模拟并发隔离。
- UI：全局设置与项目编辑器复用资源列表、搜索、草稿与状态，沿用主题与中英文本。显示“已安装/策略选中/启用配置/运行时可用”的区别。

## 2. CLI 适配决策

| CLI | MCP | Skill | 明确限制 |
| --- | --- | --- | --- |
| Claude | --mcp-config + --strict-mcp-config | --settings 的 skillOverrides；使用原生名称规则 | 普通技能控制不能推及插件；版本/来源须校验 |
| Codex | 本机直接启动使用受管项目 profile（`--profile`），失败或 WSL 回退 `-c` 配置覆盖，显式禁用未选服务器 | skills.config 按路径覆盖并写入同一项目 profile | 共享根、嵌套根、插件均计入来源分析；不能只增加选中路径 |
| Grok | 受管 GROK_HOME 的原生定义 + disabled_mcp_servers | 受管源、skills.paths/ignore/disabled 组合 | per-server enabled 会被项目覆盖；固定禁用名单不等于动态白名单；插件不受普通 ignore 完整控制 |

以上是选定实施机制，不是三 CLI 全部运行时验收已通过。Grok 启动预检须比对最终定义来源与 command/url/内容身份；同名项目定义冲突时返回冲突，不能只按名称宣称选中正确资源。

## 3. Grok 非扩展配置与状态

原始 Home 在进程注入前解析固定；保留原有 GROK_AUTH_PATH、配置环境与真实 cwd。仅给目标进程设置 GROK_HOME，不改变系统 HOME/USERPROFILE。

| 内容 | 决策 | 交付前验证 |
| --- | --- | --- |
| config.toml 与非扩展配置 | 生成保留语义的独立投影，只修改 MCP/Skills；未知字段保留、相对路径保持原目标 | 非扩展有效配置差异审计、供应商/权限/Hook/状态栏/规则等价 |
| 认证 | 优先 GROK_AUTH_PATH 指向原认证目标，共享原锁域；不复制凭据 | 真实刷新及并发锁；假认证原生读写已验证 |
| 历史 | 精确共享 sessions 等经过确认的状态根，不复制活动数据库；Windows Junction 为本地候选，POSIX 使用目录链接 | 原生追加、索引、恢复、并发与异常；假历史列举已验证 |
| bin/leader/socket/锁/缓存 | 按文件职责适配，不整 Home 链接或复制 | 子进程、运行文件冲突、重连/恢复 |

新启动/新进程恢复读取最新原始配置；现有进程保持其启动快照。认证刷新、历史新增是持续状态，不冻结为启动副本。受管会话自行更改配置不自动整文件回写原 Home；可保留于该会话，持久全局设置仍由原始配置/全局入口维护（此回写边界包含在本稿审阅中）。

## 4. 已确认的优先级与项目降级边界

V1.4.0 定位为“启动时资源选择管理”，不是 OS 安全沙箱，也不承诺用户或外部工具在会话运行期间修改发现目录后仍可持续强制白名单。原生热加载不能被 UI 的“待重启”提示伪装成已冻结。

- 普通受管资源：启动时枚举来源、解析身份、生成策略；A=ABC/B=BCD 并发及空集合在支持的来源/版本组合下必须真实成立。
- 外部、插件、内置、企业资源：仍纳入盘点与有效集合说明。只有具备可验证单项控制能力时开放单项开关；不能把普通 Skill 字段盲用到插件。
- 若 CLI 无法接管或外部/插件来源使项目控制无法可靠成立：对应项目 MCP/Skills 设置显示“无法实现项目级设置，仅支持全局 MCP/Skills”，禁用自定义，展示原因、实际全局配置与全局入口；使用全局而不伪装自定义生效。MCP/Skills 独立判断，不支持一个不关闭另一个。
- 会话运行期间新增插件/外部资源：不承诺持续强制隔离；应用自身的资源变更留待新会话。重启前重新扫描。若未来增加文件监测，只用于提示偏差，不能把轮询当成无竞态的安全保证。
- 自定义命令无法安全注入、CLI 版本不兼容、环境不支持：标为仅支持全局；不阻断正常全局会话启动。已有自定义策略失效时保留记录但标未应用，启动前提示实际将使用全局，不能静默降级。

以上降级原则已获用户明确授权，R6/R7 验收为“支持时正确应用，不支持时正确提示并使用全局”。能力按 CLI/环境/版本/资源种类记录 supported/global-only，并与 unknown/error 分离；暂时权限错误、配置损坏、同名冲突应提供修复/重试，不误标永久不支持。全局写入失败仍按逐目标失败处理，不能借项目降级掩盖。

## 5. 平台与非目标

Windows、macOS 本机及 WSL 保持既定目标，不降级为 Windows-only；缺少测试环境是发布缺项，不要求在规划阶段安装系统或反复测试。Windows Skill 链接失败可复制，认证/历史不能因此退化成独立副本。SSH、市场搜索、自动更新按既定决定延后。

## 6. 有限的实施与验收安排

规划停止条件：已确认全局优先和项目降级，不再追加能力边界访谈或泛化实验。整理后交用户审阅并获实施授权，再 start 模型任务；不要求完整项目端到端测试作为全局开工前提。

执行顺序与依赖：模型/适配器 → 导入/存储/部署 → 全局 UI → 项目 UI 与启动/恢复接线；项目任务同时依赖适配器、部署和全局可复用资源组件。Grok 状态适配在项目任务内部实施，失败不妨碍完成独立模型/导入交付，但阻止 Grok 项目能力发布。

| 验收组 | 所属任务 | 停止条件 |
| --- | --- | --- |
| 格式、未知字段、秘密、冲突 | model-adapters | 定向测试失败即修复，不进入泛化 CLI 调研 |
| 导入、路径安全、链接/复制、恢复 | import-sync | 源不受损、幂等、逐目标结果正确 |
| 主题、双语、交互状态 | global/project | 手工与组件验证通过 |
| ABC/BCD、空集合、同名冲突、仅支持全局 | project | 支持域成立；不支持项清楚提示并使用全局，独立 MCP/Skills 能力不串扰 |
| 认证刷新、历史/索引/resume、Hook、leader、快照时机 | project | 作为集成/发布门禁；有失败不得标记对应适配支持 |
| Win/macOS/WSL | 各任务 + 父任务 | 分环境实际验收，未通过不宣称全部平台交付 |

本稿批准不等于测试通过；下一步是有范围的实现与验收，不是再开“第三轮全面探索”。新发现只有改变上述机制或用户约束时才升级决策。
