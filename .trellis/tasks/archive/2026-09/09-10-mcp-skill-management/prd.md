# V1.4.0 MCP 与 Skills 全局及项目管理

## Goal

实现 #204、#243：首要目标是 Claude Code、Codex CLI、Grok Build 的全局 MCP/Skills 管理，实现“一处维护、各 CLI 使用”；其次才是按 CLI 能力提供项目 A=ABC、B=BCD 的独立加载集合。项目能力无法实现时明确仅支持全局管理，不阻塞全局交付。

## Scope and approval status

用户已授权创建任务并指定 V1.4.0，现已明确要求按计划实施。四个子任务已按依赖顺序完成产品实现、审计和独立提交，当前进入父任务集成验收记录。
用户已确认：项目策略仅对 CLI-Manager 启动的会话生效，包括由 CLI-Manager 创建的新进程和恢复会话；外部终端直接启动 CLI 不属于项目策略应用范围。
用户已确认 V1.4.0 必须支持 Windows、macOS 本机和 Windows 下的 WSL，覆盖全局管理、导入、Skill 同步与项目策略。
用户已允许为 CLI-Manager 启动的 Grok 接管 GROK_HOME，条件是继承原始 Home 的全部配置，仅注入/覆盖 Skills 与 MCP。此授权不包括改写原始 Home 的其他配置，也不代表受管 Home 已通过兼容验证。
当前技术路线与能力边界入口为 decision.md。用户要求停止泛化测试轮次，认证刷新/历史恢复/长驻进程/跨平台验证转为实施阶段的集成和发布验收；现已授权按计划实施，未取消验收。
用户已确认项目能力降级：实施中发现 CLI 无法接管或无法实现项目 MCP/Skills 策略时，在对应设置明确说明“无法实现项目级设置，仅支持全局 MCP/Skills”，使用全局配置且不声称项目策略生效。MCP/Skills 分别评估；此约定取代此前必须实现所有 CLI 项目隔离或阻断启动的建议。

## Scenario acceptance

- 多窗口/分屏/Workspan、最小化、侧栏折叠、焦点模式：按稳定项目/会话身份归属，不依赖当前焦点。
- Windows 本机 PowerShell/CMD/pwsh/Git Bash、macOS 本机默认 zsh 与已支持 Shell、WSL：Home、路径、命令引号和部署环境正确；无 Hook 仍可管理。
- Windows、macOS、WSL 分别验收三个 CLI 的格式转换、cc-switch 导入、软链接/复制和 A/B 并发隔离；不可用 CLI 或未验证场景必须记录，不能把单平台通过视为全部支持。
- SSH 项目不展示可用的写入/策略应用操作，明确提示本版未支持，不回落本机执行。
- Worktree 的 .git 文件、目录缺失、同路径不同项目、恢复/daemon 重连：不误写或重用其他作用域快照。
- 共享 Skill 目录、插件来源、同名异内容、外部修改、软链接失效：不能以移除一个链接宣称完整禁用。
- 外部工具并发写配置：冲突不覆盖；部分成功结果可重试且幂等。

## Deferred scope

SSH远端管理、市场搜索和自动更新不属于V1.4.0。全局管理仍维护用户选择的全局默认。

## Technical notes and integration acceptance

选定 Claude 原生启动覆盖、Codex 配置覆盖、Grok 受管 Home 候选路线；详细机制、证据与不支持状态见 decision.md。仅通过对应验证才开放项目能力；验证失败按已确认规则显示仅支持全局，不继续为项目能力阻塞全局主线。
受管 GROK_HOME 必须通过 R6/R7/R9 联合验收：除 MCP/Skills 外，有效配置语义、相对路径解析、认证、供应商、权限/企业限制、Hook、状态栏与历史恢复保持原行为；不能以重新登录、丢失历史或关闭整个插件作为默认代价。复制 Skill 的回退规则不得直接套用到认证、数据库或 socket。

用户已确认：新启动或恢复并创建新进程时重新继承原始 Home 的最新配置；现有进程保留启动快照，重连不重新注入。原始非扩展配置变化不自动热更新已有进程，显示待新会话应用。认证刷新和会话持久化属于状态连续性，不能靠冻结配置快照替代。
验收：启动 A 后修改原始非扩展配置，再启动 B，A 保留原基线、B 使用新基线，各自 MCP/Skills 策略不变；重连 A 保留原快照，创建新进程恢复 A 使用最新基线。认证刷新与历史新增仍正常持久化。

## Delivery priority and fallback acceptance

第一阶段验收 R1–R5、R8–R10 的全局部分：资源编辑后向所选 CLI 投影/同步并显示逐目标结果，不要求维护多格式。原生不兼容字段和失败不得静默忽略，“到处使用”不意味着所有 CLI 功能完全相同。
第二阶段验收 R6/R7 与项目 UI：按 CLI/环境/版本分别评估 MCP、Skills；支持项真实生效，不支持项显示中英文说明、实际全局状态及全局设置入口。项目不支持不阻塞正常全局会话启动；已有自定义失效时启动前明确告知未应用及改用全局。
权限不足、配置损坏、冲突等可修复错误单独报错，不当作永久不支持或隐式覆盖原配置。项目仍为启动时配置管理，不承诺运行期外部新增资源的持续强制白名单；不以关闭整个插件破坏其他功能。受管配置不自动整文件回写原 Home。
