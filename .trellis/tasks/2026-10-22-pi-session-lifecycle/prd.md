# Pi 会话重建后恢复状态与清除旧错误

## 目标

修复 Pi 出错后执行 `/new`，新会话仍显示旧错误、后续任务无法恢复正常状态的问题。应用版本保持 `1.4.4`，Pi 托管模板从 v10 升至 v11。

## 已确认的根因

本机 Pi `1.4.0` 的 `AgentSessionRuntime` 在 `/new`、`/resume`、`/fork` 时先发 `session_shutdown`，销毁旧 runtime，再创建资源加载器并重新调用扩展工厂。已安装的 CLI-Manager 扩展 v10 错误地在这些边界保留旧租约，新工厂因租约占用直接返回，导致后续状态停报。现有用例只修改原扩展的会话 ID，没有模拟重建。

另一个状态缺口是普通 `SessionStart` 只负责绑定会话，不清除旧终态；宠物E还会保留旧红蓝历史。完整修复必须同时处理源状态与历史，不能只隐藏错误颜色。

## 验收要求

1. 错误后 `/new` 能完成根实例租约交接，新实例继续上报；连续切换、resume、fork、reload 同样有效。
2. 正式 Pi `SessionStart` 清理旧任务状态，空会话为空闲；开始新任务后才显示运行，失败/结束继续正常上报。
3. 前端、daemon 与宠物E状态一致；旧后台缓存和 TUI 重绘不能复活旧错误或伪装成新任务。
4. 不影响其他 CLI 的 SessionStart、普通终态历史、真实待答优先级和只读等待通道。
5. 保留父子实例隔离、单调实例/运行代际/序号、过期回调保护、WSL 身份、2 秒请求超时和已有安全代答。
6. 只修改 CLI-Manager；不修改 Pi/rpiv 源码或用户已安装的托管副本。主要业务放外挂文件，上游只保留必要薄接点。

## 交付边界

用户已批准完整修复并建任务。只做静态核查，不编译、运行测试、启动应用或安装依赖；暂不提交、推送。新增/更新用例交由用户执行。Hook 模块关闭或未安装时不猜测新会话状态，既有模块开关保持有效。
