# 文件夹独立排序与继承偏好

日期：2026-11-18。起点：`6fe6a33f`，基于已同步 V1.5.1 的 fork。
本文件定义需求，`design.md` 定义技术决策，`implement.md` 定义实现与验收。

## 目标

当前文件面板只有顶部全局排序，同一套规则递归作用于整棵树。
为每个文件夹增加同一行的排序箭头，让用户按文件夹选择名称/修改日期与升降序，并记住选择。
用户已确认：子文件夹默认继承父级，可以单独覆盖；不采用每层互不继承的方案。

## 需求

### 排序与继承

- R1. 文件树中每个文件夹行提供排序箭头，打开现有风格菜单；文件行不增加排序按钮。
- R2. 支持名称升序/降序、修改日期由新到旧/由旧到新，沿用目录优先、自然名称和未知时间后置规则。
- R3. 文件夹的设置作用于其直接内容以及未被更深层独立规则覆盖的后代；不改变同级其他文件夹的内部排序，也不决定自身在父文件夹中的位置。
- R4. 最近的显式祖先规则优先；没有祖先规则时使用现有顶部全局默认。修改父级或全局默认不删除子目录已保存的独立规则。
- R5. 菜单提供“恢复继承”，只删除当前文件夹的独立设置，保留其后代独立设置。主动选择与当前继承值相同的规则也建立独立设置，以便固定该规则。

### 展示、偏好与边界

- R6. 箭头显示有效方向，并用提示及菜单文案区分“独立设置”“继承自父级/全局默认”；紧凑目录 `a/b/c` 的菜单提供作用目录选择，默认作用于可见末级 `a/b/c`，其余层级仍可设置。
- R7. 偏好按项目、实际文件根和相对目录隔离，重启后恢复；同项目不同 Worktree、SSH 主机和远程根之间不互相覆盖。左侧栏与终端嵌入文件面板共用真值及写入队列。
- R8. 点击、双击、触摸或键盘操作排序控件不触发目录展开、多选、拖拽、复制、粘贴、删除或重命名。菜单保存失败保留旧状态并可重试；切换项目不能将旧菜单操作写入新项目。
- R9. 保持按需加载、Git 慢查询首屏、搜索结果原顺序、选中项、展开路径和编辑器缓冲不变。本地、WSL、SSH 只读文件树均可调整显示排序；不要求对远端文件有写权限。
- R10. 新文案覆盖中英文；控件可聚焦、菜单支持方向键/Home/End、Esc 关闭并恢复焦点，窄面板不覆盖文件名或 Git 标记。新偏好纳入现有 preferences 备份分类。

## 已定产品决策

- 继承父级且允许更深层覆盖（session-settled: user-approved — chosen over 每层独立回落全局默认: 用户选择推荐的继承方案）。约束 R3–R5。

## 验收示例

- AE1（R2–R4）：全局为名称升序，`logs` 设日期降序；`logs` 内及未覆盖的 `logs/archive` 按日期降序，`src` 仍按名称升序。
- AE2（R3–R5）：`logs/archive` 单独设名称降序后，改变 `logs` 为日期升序；`archive` 内仍为名称降序。恢复 `archive` 继承后变为日期升序，其更深层独立规则不丢失。
- AE3（R5）：`src` 当前继承名称升序，用户主动选择相同规则；随后全局变日期降序，`src` 仍保持名称升序。
- AE4（R6、R8）：在 `a/b/c` 紧凑行打开箭头，选择作用目录 `a/b` 并设日期降序；保存不展开/收起目录，也不更改选中项；再次打开能看出当前作用目录与规则来源。
- AE5（R7–R9）：两个同项目不同根的 Worktree 都有 `src`；只设置其中一个，另一个不变。已排队保存后切换项目，写入仍属于原捕获作用域，新面板不被旧回执改写。
- AE6（R7、R8、R10）：左侧栏与嵌入面板连续设置不同文件夹，两个选择均保留；保存失败不显示为成功，下次重试仍可完成，重启及偏好备份恢复后显示一致。

## 范围与假设

- 顶部箭头继续管理所有项目共享的全局默认，不改为项目根独立排序入口。
- 本轮按路径记忆显示偏好：重命名/移动后的新路径按新位置的有效规则显示，不自动追踪旧文件夹身份；原路径记录不据不完整树数据自动清理。
- 不增加大小/类型/自定义拖拽顺序，不修改后端目录枚举或文件系统，不改 Web/Tap 文件浏览器，不改数据库/IPC/认证。
- 保留原有 fork 外挂方式；共有文件只留必要接线，新逻辑以独立文件承载，变更手写代码不得超过 2000 物理行。
- 只进行静态检查；编译、行为测试、浏览器和实机验收由用户执行。完整架构检查仍受已有依赖缺失及未改 broker 超限影响，不声称全仓通过。
- 方案完成后确认本轮实施及交付范围；上一任务的合并推送授权不自动扩大到本功能。版本记录拟沿用 V1.5.1 fork 小节，待用户确认，不升应用版本。

## 完成标准

R1–R10 的源码接线和回归覆盖齐备；AE1–AE6 作为用户运行验收场景；静态结果与未执行项分别记录。
无无关文件移动、批量覆写或上游大模块重构；未跟踪旧任务、主 worktree 和安装副本保持原样。
